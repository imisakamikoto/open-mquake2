# 御坂防灾（Mquake 2.0）

用 Flutter + Rust 重新实现的地震监测客户端，替代原先基于 Leaflet + jQuery 的
Web 版本。旧的 8300 行 `index.js` 被拆分为一个可测试的 Rust 计算核心与一个
Flutter 界面层。UI 采用 Material Design 3 深色沉浸式设计。

**地图采用与 mquake1.0 相同的 Leaflet 式地图模型**（`flutter_map` 是 Leaflet
的 Dart 实现：`PolygonLayer / PolylineLayer / CircleLayer / MarkerLayer` 一一
对应 `L.polygon / L.polyline / L.circle / L.marker`），图层、配色、缩放范围、
自动视角与交互都按 1.0 对齐；自研的 Canvas 渲染管线（`rust/src/map/render.rs`
→ `RenderCommand` → `CustomPainter`）已弃用。

## 目录结构

```

│   └── src/

│       ├── map/              # 【已弃用】自研渲染管线，仅保留源码不再被 Dart 调用
│       ├── seismic/          # 震相走时、震度换算、震中定位、等值线
│       ├── model/            # 领域模型（serde）
│       ├── geojson.rs        # GeoJSON 解析
│       ├── color.rs          # 色表 / 颜色渐变
│       └── api.rs            # C ABI 桥接层（JSON 进出）
└── app/                      # Flutter 应用
    └── lib/
        ├── src/map/          # Leaflet 式地图（图层 / 配色 / 自动视角）
        ├── src/models/       # Dart 模型
        ├── src/services/     # 数据 / EEW / 音频 / 设置服务
        ├── src/state/        # Riverpod 状态

```

## 架构总览

- **Rust 核心是纯函数库**：输入 JSON，输出 JSON，不持有网络连接、不读文件、
  不依赖平台。所有震级/震度/走时/地震定位逻辑都在这里，可 `cargo test`。
- **Dart 负责一切 I/O**：HTTP、WebSocket、音频播放、TTS、本地设置持久化。
- **服务端已内置**：应用内的 `AggregationService` 直连各上游数据源并本地聚合，
  不再依赖部署的 `all.js` / `cencking.js` 等服务端（详见
  [docs/SERVER_INTEGRATION.md](docs/SERVER_INTEGRATION.md)）。
- **桥接面保持极简**：Rust 编译为动态库（DLL），Dart 通过 `dart:ffi`
  调用；跨语言边界只传 JSON 字符串与基础数值，避免结构体镜像。
- **Leaflet 式地图**：`FlutterMap` = `L.map`，各 `*Layer` = `L.geoJSON` /
  `L.circle` / `L.marker`，`controller.move / fitCamera` = `map.setView /
  fitBounds`。底图是矢量（海洋底色 + 世界陆地 + 海岸线），图层顺序按 1.0 的
  pane z-index 排列。

详见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 与
[docs/MAP_PIPELINE.md](docs/MAP_PIPELINE.md)。

## 测站数据源

地图上的测站点是多个源合并的结果（`HomeScreen` 里拼成一份 `stations`）：

| 源 | 方式 | 说明 |
| --- | --- | --- |
| K-NET（NIED） | 每 `knetIntervalSec` 秒抓实时震度图，按点位取色 | 日本陆地强震台网 |
| S-net（MSIL） | 每 `snetIntervalSec` 秒拼 smoni 瓦片取色 | 日本海底台网，默认关闭 |
| SeisJS（Wolfx） | WebSocket `wss://seisjs.wolfx.jp/all_seis` 推送 | 民间台站，每站每秒一帧 |

SeisJS（`lib/src/services/layers/seisjs_service.dart`）：

- 测站列表 `https://api.wolfx.jp/seis_list.json` 每 10 分钟拉一次，用来做**云控**
  （`enable=false` 的站不下发）和取位置名；
- 服务端每分钟发 `heartbeat`，客户端回 `ping` 保活；超过 2 分钟没报文自动重连；
- 震度口径统一用 **JMA 震度**（`CalcShindo` 计测震度，缺失时退回 `Shindo` 文本
  `5弱/5強` → `5-/5+`），与 K-NET 图层量纲一致；`Intensity`（CSIS 烈度）暂不使用；
- 门槛沿用现有的「测站最低震度」（测站数不设上限，五个源全量绘制），开关在设置 → 地图图层。

### 震度轴的下界是 −3：换算结果低于它一律夹到 −3

各源的「静止」读数并不一样，但本应用的震度轴下界只有一个：**−3**（K-NET 静默站的换算值，
也是「测站最低震度」的默认档「全部显示」）。低于 −3 会同时踩两个坑：

- 过不了默认门槛 −3，整批测站**永远不显示**；
- `MapStyle.stationDotColor` 对 `shindo < -3` 返回 null，圆点**根本画不出来**。

而「比静止更静」没有物理意义，只是各源计测公式的噪声底。典型是 Wolfx：`CalcShindo`
是连续计测震度，静默时可以到 **−4.7**（实测成都站），噪声大的站更低 —— 于是这些站长期
不显示，落在 −3 附近的则**每秒闪进闪出**。现在各源换算一律过 `kQuietShindo` 夹断：

| 源 | 静默读数 | 处理 |
| --- | --- | --- |
| Wolfx SeisJS | `CalcShindo` 可到 −4.7 以下 | 夹到 −3（`normalizeSeisjsShindo`，上界 8） |
| P-Alert | `PGA = 0` → 公式得 −∞ | 直接给 −3（以前返回 null，整站被丢） |
| K-NET / S-net | 静止就是 −3 | 无需处理 |

另外两类「测站凭空消失」的通道也堵上了：

- **震度缺失**（测站刚上线 / 传感器报错时会有几帧没有 `CalcShindo`）按静止 −3 显示，
  不再把整站丢掉；
- **测站列表被腰斩**（上游偶尔返回截断的 `seis_list.json`）时不替换元数据，避免一大批站
  因为「列表里没有 / 被标成 `enable=false`」整批消失、还要等下一个 10 分钟周期才恢复。

数据源状态面板里 SeisJS 会显示「收到 N 站 / 显示 M 站」：两个都掉说明是链路问题，
N 有 M 没有说明被门槛或云控滤掉了。

### KMA（韩国）的 진도 要换算成震度，不能直接用

KMA PEWS 每站给的是 4 bit 档位，解出来是 **0 基的 MMI 序号**（`-1` = 무감、`0` = 진도 I、
……、`11` = 진도 XII），而且 KMA 的 진도 本身就是 **개정 메르칼리 진도（MMI）**，和 JMA
震度不是同一把尺。两者的**等级序号是一一错开的**：

| MMI（진도） | I | II | III | IV | V | VI | VII | VIII | IX | X |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| JMA 震度 | 0 | 1 | 2 | 3 | 4 | 5弱 | 5強 | 6弱 | 6強 | 7 |

也就是说 **진도 VI 已经是「震度 5 弱」，不是震度 6** —— 高段被 JMA 的半级压掉了一半。
以前直接把档位当震度用，韩国中等地震（最大 진도 VI~VIII）会被画成震度 6~8，而震度
图标到 7 就封顶了，等于全屏最高档；`mmi = 11` 甚至能算出 11.0 这种轴外的值。
现在按上表查 `mmiShindoTable`（`mmiToShindo` 对非整数还做线性插值，保证单调），
最强也只给到震度 7。无感与 진도 I~II 三档仍压到 `-1` 不点亮图标 —— 平时两百多个站里
总有一小撮停在这几档。

## 本地震源推算（不依赖紧急地震速报）

EEW 有发布门槛（M3.5 以上 / 最大震度 3 以上），达不到就不会发报，震央也就无从得知。
所以应用自己也从测站的**揺れ検知时刻**反推震源。方法来自
[Kotoho 的文章](https://note.com/kotoho7/n/n59e423877b1b)，在这个骨架上补了几层：

1. **记录検知时刻**：每个测站「开始摇」的那一下记下来，之后的观测不再更新时刻。
   判定门槛默认**自适应**（按这台站自己的本底噪声），也可以切回固定档位；
2. **仮震源**：不止一个起点。原文的「最早检知点」+「到时加权重心」+
   （单侧覆盖时）「空档方向 90 / 180km 外各一个」，一起做谷底下降取最好的；
3. **误差レベル**：用走时表把每个检知点的到时换算成「发震时刻」，取**稳健加权**
   方差（Huber 两轮重加权，权重还乘上震中距与数据源可信度）；
4. **着未着法**：検知点还很少时（震后 3 秒内，或 10 秒内不足 30 点），对「按当前
   震源算早就该震到、却没检知」的测站罚分——但只罚「按振幅算真的该摇到」的站，
   总分也封顶，免得几千个静默站把代价彻底带偏；
5. **谷底下降**：0.5° 四邻域 → 0.1° 四邻域 → 深 ±50km → 深 ±10km → 0.02° 收尾，
   逐轮把仮震源挪到误差更小的候选，直到没有改善。

### 检知门槛：默认自适应，检知点不设上限

固定门槛两头不讨好：底噪大的站天天误触发，安静的站要到震度 2 才认。现在每台站
记一条「平时有多安静」的基线（震度与抖动的指数滑动平均，时间常数 10 分钟），
检知条件是 **震度 ≥ 基线 + max(1.0, 3σ)**，再夹一个 0.5 的下限：

- 平时 −3 ~ 0 的安静站，0.5 就算检知（比固定 1.5 早好几秒，多好几个点）；
- 平时自己在 1.0 上下抖的站，要抖到 2.0 才算（固定门槛会误触发）；
- 基线只吸收「没被记为检知」的观测，正在摇的站不参与，否则地震一来基线就被抬走。

**检知点数量不设上限**（以前满 120 个就不收）。搜索阶段取「最先到的 1/3 + 其余
等间隔抽」共 64 个点压住开销，**最终评分与残差统计永远用全部检知点**。

### 海域：S-net 不参与，靠「空档方向 + 浅源先验」

- **S-net 海底测站不参与本地推算**。它是按分钟发布的瓦片产品（时标只到分钟、
  震度还被量化到色阶），拿它算到时只会得到「整帧同时检知」的假信息。海面上的
  定位改由陆地台网 + 下面的几何处理来做。
- 陆地台网看海上地震时，检知点全在一侧（实测方位角空隙 240°+）。解算会：
  1. 往**空档方向**（用最大方位角空隙的中心定出来）多放两个起点，
     否则谷底下降会沿着海岸线打转；
  2. **振幅约束**：有震度观测的检知点同时参与距离衰减拟合（司・翠川 1999），
     反解规模 M 并把震度残差加进代价——「深一点 / 远一点」和「浅一点 / 近一点」
     走时几乎一样，震度随距离单调衰减才能把两者分开；
  3. **浅源先验 + 深度平台**：代价里加 `0.3·(深度/100)²`，并在最优水平位置上
     扫一遍深度，把「残差比最优多 0.4 秒以内」的深度区间如实报出来
     （`depthUncertainKm`），区间很宽时取最浅端——俯冲带近海地震就是这么浅，
     报一个「深 100km 的近海地震」比报「浅、但深度不确定」危险得多。
- 搜索范围限制在检知点重心 400km 内：信息不足时代价面是平的，谷底下降会沿着
  平地一路滑到上千公里外（实测过）。这是**物理约束**，不是调参。

### 防误检：一致性闸门

解完之后还要过闸门，任何一条不过就**不发结果**（`lastRejectReason` 里能看到原因）：

| 闸门 | 挡什么 |
| --- | --- |
| 内点 ≥ 4 / 残差 ≤ 3s | 到时根本解释不通的噪声 |
| 最大站间距 ≥ 50km | 一个城市里的局部振动 |
| 至少 3 个不同的检知时刻 | 整帧同时检知（没有任何传播信息） |
| 秩相关 τ ≥ 0.35（仅在残差 > 1.2s 时看） | 「远的先摇」这类完全乱套的到时 |

### 自我学习

`hypo_learning.dart` 把每台站、每个数据源**系统性地报早/报晚**多少记下来
（`data/hypo_learning.json`），下次解算先扣掉，相当于给每台站各做一次钟差校准：

- 源偏差与站偏差**正交**：先按源算这一场的平均残差，站偏差再用「残差 − 源平均」学，
  否则同一份残差会被加两次；
- 只在解本身可信时学（内点 ≥ 8、残差 ≤ 2.5s、方位角空隙 ≤ 270°），单条残差超过
  3 秒直接当离群丢掉，偏差上限 ±2.5s（源 ±3s、合计 ±4s）；
- 样本少时按 `samples / 6` 打折使用；写盘节流 20 秒，退出前强制写一次。
- 实测：让 K-NET 整体晚报 2 秒，14 轮后源偏差收敛到 +0.45s / −0.50s，
  到时残差从 0.98s 降到 0.49s。
- 设置里可整体关掉，也可以「清空」学习数据。

### 内置小模型：拿官方后续报告对答案

站点偏差只解决「到时不齐」。几何解算还有一类**有结构**的误差：海上单侧覆盖时
震源沿空档方向滑、只有振幅没有到时的时候深度会飘、某些台网密集区整体偏一个方向。
这些不是随机噪声，是可以学的。`evo_model.dart` + `evo_evolver.dart` 用一个
**15 → 12 → 5 的两层小网络**（244 个参数，纯 Dart，单次前向不到一微秒）来学它：

| 输入（解算自己的体检报告） | 输出（相对未修正解的偏差） |
| --- | --- |
| 残差、内点数与内点占比、方位角空隙、是否单侧 | 北向 km、东向 km |
| 深度与深度不确定度、检知点最大间距、规模 | 深度 km、规模 |
| 平均绝对残差、S 波拟合占比、报数 | 发震时刻秒 |
| P-Alert / KMA 检知占比（不同台网的时延差异） | — |

**训练数据从哪来**：聚合服务每 3 秒推一次事件列表，`HypoService.ingestOfficial`
把官方的**后续报告**（JMA 地震情报、速报最终报、EMSC/USGS/CENC 的修订版）
按「发震时刻 ±180 秒 + 震中 500km 内」匹配到刚才那几次本地解上，取
「官方值 − 本地未修正解」当目标。权重按源给：JMA 定测 1.0、CENC 0.95、
USGS 0.85、EMSC 0.72、速报 0.75；最终报再额外加权。

**四条纪律**（不然一个小模型足以毁掉整个定位）：

1. **未训练 = 恒等**：输出层的权重与偏置初始化为 0，没有样本时一个数都不改；
2. **信任度爬坡**：修正量按 `样本数 / 40` 打折，3 条样本只敢改一点点；
3. **硬上限**：位置 80km、深度 ±50km、规模 ±0.6、时刻 ±4s；
4. **验证闸门**：每 5 条抽 1 条做留出集，每轮训练后复核，验证误差变差超过 2%
   就把权重整个回滚（`通过 / 回滚` 两个计数器直接显示在设置页上）。

写盘在 `data/hypo_model.json`（权重 + 训练/留出样本 + 统计），节流 10 秒，
退出前强制写。同一份官方报文反复推只学一次（键是「源 + 事件 ID + 官方解指纹」），
速报修订出新的震源参数才算新样本，每个事件最多 3 条。

实测（合成数据，本地解固定偏南 25km）：60 场之后模型学到 +25km 的北向修正，
修正后残差降到 8km 以内；只有 3 条样本时修正量不到 12km。

代码在 `lib/src/services/hypo/`：

| 文件 | 作用 |
| --- | --- |
| `hypo_estimator.dart` | 稳健加权 + 振幅约束 + 多起点 + 深度平台（核心算法） |
| `attenuation.dart` | 计测震度的距离衰减式、由震度反解 M |
| `azimuth.dart` | 方位角 / 包围程度 / 空档方向 |
| `shindo_picker.dart` | 揺れ検知追踪（自适应门槛、噪声基线、事件窗口、来源过滤） |
| `hypo_learning.dart` | 站点/数据源到时偏差的学习与落盘 |
| `evo_model.dart` | 内置小模型（15→12→5 全连接网络、特征、修正量与硬上限） |
| `evo_evolver.dart` | 官方报告匹配、样本缓冲、验证闸门、模型落盘 |
| `hypo_service.dart` | 测站流 → 震源估计流（2 秒重算、一致性闸门、学习与小模型调度） |

走时优先用 Rust 侧加载的 `assets/js/traveltime.txt`（JMA2001 系列，深度 0–890km、
震中距到 10800km），表没加载时退化为分层近似（直达波 / 莫霍首波取较早者）。
发震时刻是副产品：每个站反推的发震时刻的（稳健）加权平均就是输出里的「发震」时间。

**精度**：合成数据（到时量化到整秒 + ±0.4s 抖动，模拟真实上游精度）下，震中误差
1–9km；端到端（测站流 → 震源）0km 级；海上单侧场景 2–9km，深度会如实标成
「深 5 ± 90km」。真实数据的瓶颈是**检知时刻的时间分辨率**——K-NET 默认每 10 秒
抓一帧，同一帧里所有站共享一个时间戳，想要更准就把设置 → 刷新里的「K-NET 刷新
间隔」调到 1~2 秒（P-Alert / KMA 本来就是 1 秒一帧）。深度是弱约束，围住的台网
一般 ±20km，单侧覆盖时基本只能给个上限。

**界面**（`map/layers/hypo_layers.dart` + `ui/hypo_card.dart`）照 JQuake 的揺れ検知排：

- **暗蓝小点**＝还没摇的静默测站（K-NET 点位表 + SeisJS 列表，上千个点用一个
  `CustomPainter` 画，不走 `CircleLayer`，否则平移会卡）；
- **亮青点**＝已经检知的测站，光晕让它像被波前点亮——播报过程中能直接看出揺れ
  是怎么一圈圈推开的；
- **红白十字**＝推算震源，**白虚线**＝P 波前缘（6.7km/s），**橙红虚线**＝S 波前缘
  （3.9km/s，所以半径小）；
- 卡片里另外给出：第几报、规模 `M`（由振幅反解）、内点/外点、`score`/`rms`、
  方位角空隙、`S-like`（用 S 波解释更顺的站数）、静默站数、深度不确定范围；
  小模型出手时再多一段 `模型 Δxx km`——让用户看得见「这一版不是纯几何解」。

**重要**：这一层绝不覆盖测站本身的震度颜色——检知点只在图标外面套一个空心环
（半径 13 > 图标 11），中心留空。

开关在设置 → 本地震源推算：启用 / 检知门槛自适应 / 自我学习 / **内置小模型**，
四个开关互相独立，改完当场生效（不用重启）。

## 测站信息卡（放大后显示）

地图放大到一定级别，每个测站旁边会浮出它自己的读数（`map/layers/station_label_layers.dart`）：

| 缩放 | 显示内容 |
| --- | --- |
| < 8.5 | 只有圆点 / 震度图标 |
| 8.5 ~ 9.4 | 一行：`站名 震度`（此时站间距只有几十像素，三行卡片会互相压住） |
| ≥ 9.5 | 三行卡片：`站名` / `加速度 xx gal` / `震度 x.x` |

规则：

- 只画视口内的站；按震度降序、同震度按离画面中心由近到远排序，一屏最多 32 条
  —— 有地震时先标出最剧烈的站；
- 每条文字有右 / 左 / 上 / 下四个候选位置，挑第一个既不压别的文字、也不压任何
  测站点位的；四个位置都不行就不画（测站本身的震度颜色绝不被遮住）；
- 锚点几乎重合的站（不同数据源在同一地点各放一个）只标震度高的那个；
- 锚点到文字块之间有一根半透明引导线，密集时才分得清哪行字属于哪个点。

开关在「设置 → 地图图层 → 放大后显示测站信息」。相机上限同时从 10 提到 11，
否则三行卡片几乎没有可用的缩放区间。

## 预警的生效判定：一事件多报只算一条

JMA 的紧急地震速报是**一事件多报**：`EventID` 相同、报号（`Serial`）一路递增
（第 1 报 → 第 2 报 → …… → 解除报），各源同理（成都高新 `updates`、Trem `serial`、
CENC `serial_number`）。速报缓存 `_eewStore` 按 `EventID_报号` 留住每一报（历史要留），
但**「生效列表」必须按 `eventId` 归并，只留最新一报**：

- 解除 > 报号 > 发布时刻（`AggregationService.preferReport`）。解除优先是因为它是
  这个事件的终态，必须能顶掉前面的推测，否则预警条会一直显示旧的最大震度。
- 生效窗口 60 秒（发震 / 发布时刻**任一**在窗口内），解除报同样受约束，否则
  「预警时隐藏测站」永远不会恢复。

以前去重键带了报号，等于把每一报都当成独立的生效事件：预警面板显示「1 / 5」并在
同一个地震的 5 份报之间轮换（真正「同时多个地震」反而被挤没了）、地图上同一震源
叠着 5 圈震波、侧栏「预警」聚焦的 `events.first` 可能落到已经过期的旧报（同一事件
各报的 `originTime` 相同，`sort` 不稳定，谁在第一个是不确定的）。

回归测试：`test/active_eew_test.dart`（6 例）。

## 开发版水印

编译产物默认带开发版水印（内测分发时用来区分版本、定位是哪台设备反馈的问题）：

- **整屏平铺**：-30° 斜向重复 `开发版 v2.0.0+1 · MQ-1A2B-3C4D-5E6F`，透明度 8.5%，
  包在 `IgnorePointer` 里，不影响地图拖动/点击；
- **左下角标签**：显示版本号与设备标识，点一下即可复制（贴给开发者就能对上号）；
- **设置 → 开发版**：可以单独关掉水印，也能看到/复制本机标识。

版本号来自 `pubspec.yaml` 的 `version:`，`build.ps1` 每次编译会把它同步到
`lib/src/core/app_version.dart`（水印读的就是这里），所以不用手改代码。

设备标识（`lib/src/services/device_id_service.dart`）：

1. Windows 读注册表 `HKLM\\SOFTWARE\\Microsoft\\Cryptography` 的 `MachineGuid`
   （Linux 读 `/var/lib/dbus/machine-id`），经 FNV-1a 摘要后得到 `MQ-XXXX-XXXX-XXXX`；
   同一台机器每次启动都一样，不含任何个人信息、也不上报；
2. 拿不到机器指纹时随机生成一个，写入运行目录的 `data/device.json`，每台设备首次
   启动各生成一次；
3. 整个程序目录被复制到另一台电脑时，指纹对不上会自动重新生成，不会两台设备共用
   同一个标识。

正式分发时用 `build.ps1 -NoWatermark`（即
`--dart-define=DEV_WATERMARK=false`）编译，水印代码会被树摇掉。回归测试见
`test/device_id_test.dart` 与 `test/dev_watermark_test.dart`。

## 系统托盘与预警弹出

这个应用本来就该一直开着等着，所以最小化（或关闭）默认不是退出，是**缩到系统托盘**：
数据源轮询、音效、语音播报全部照常跑，只是窗口藏起来了。

- 开关在「设置 → 窗口」：`最小化 / 关闭时缩到系统托盘`（默认开）。
  缩到托盘后托盘里常驻图标，**右键 → 打开主窗口 / 退出**（退出是唯一的退出路径）。
- `预警 / 海啸 / 强震动时弹出窗口并置顶`（默认开）：

  | 触发 | 时机 |
  | --- | --- |
  | 预警 | 紧急地震速报（预报 / 警报 / 更新）响音的那一条 |
  | 海啸 | 新发或升级的海啸警报（大津波 / 津波 / 注意报），解除不弹 |
  | 强震动 | 实时震度或 PGA 跨过提示音门槛的那一次 |

  弹窗 = 从托盘恢复窗口 + 闪任务栏 + 置顶 **20 秒后自动放下**（不永久压着）；
  同一类事件 **30 秒冷却**，速报更新报一秒一条也不会反复抢焦点。

- 实现：原生 `windows/runner/tray.{h,cpp}`（`Shell_NotifyIcon` +
  `SetWindowPos(HWND_TOPMOST)` + `FlashWindowEx`），Dart 侧
  `services/window_service.dart`，走 MethodChannel `mquake/window`。
  ⚠️ runner 的 C++ 源文件必须 **ASCII-only**，界面上的中文一律写成 `\u` 转义
  （MSVC 用系统代码页读源码，`/WX` 会把 C4819 变成错误）。
- 非 Windows 平台通道调用返回 false 并静默跳过（不会因为没实现而抛异常）。
- ⚠️ 托盘图标用的是 `NOTIFYICON_VERSION_4`，回调消息的打包方式和老版本不同：
  **事件在 `LOWORD(lParam)`、图标 id 在 `HIWORD(lParam)`、`wParam` 是坐标**
  （老版本是 `wParam` = 图标 id、`lParam` = 事件）。按老写法解析的话右键菜单
  永远不会弹出来。菜单本身由一个 0×0 的离屏工具窗口持有（主窗口藏在托盘时
  不能抢前台，`TrackPopupMenu` 就拿不到点击）。

## 质量监控（Sentry）

崩溃与未捕获异常可以上报到 Sentry（`services/monitoring.dart`）。**没配 DSN 时
整套监控不启动，一条请求都不会发**，所以默认分发出去的包依然是纯本地的。

配置方式（二选一，DSN 属于部署凭证，不进仓库）：

1. 编译期注入：
   ```powershell
   flutter build windows --dart-define=SENTRY_DSN=https://…@o…ingest.sentry.io/… `
                         --dart-define=SENTRY_TRACES_RATE=0
   ```
2. 运行目录 `data/sentry.json`（与 `settings.json` 同级，`app/data/` 已被 gitignore）：
   ```json
   { "dsn": "https://…", "enabled": true, "tracesSampleRate": 0,
     "includeDeviceId": false, "environment": "release" }
   ```

行为：

- `SentryFlutter.init` 包住 `runApp`，Flutter 框架错误、Dart 异步异常都会被接住；
  版本号写成 `mquake@<version>+<build>`，环境按构建模式取 `release` / `profile` / `debug`；
- `sendDefaultPii = false`：不带主机名 / 用户名。设备标识（水印那串）默认也**不带**，
  只有显式打开 `includeDeviceId` 才作为 `device_id` 标签上报；
- 采样率默认 0，只报错误不采事务；
- 「设置 → 诊断 → 上报崩溃与错误」是用户随时能拨的开关（默认开）；
- 上报失败 / 没配 DSN 都静默处理，绝不影响启动。

回归测试见 `test/monitoring_test.dart`（12 例：DSN 形状校验、配置合并优先级、
坏配置兜底、未启用时全部空操作）。
